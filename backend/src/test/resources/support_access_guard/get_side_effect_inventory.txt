# F10.9 サポート閲覧（戦役Z-B）: GET の副作用の洗い出し表。
#
# 代理閲覧は「閲覧のみ」。DB 接続は READ ONLY のため書込は例外になるが、GET が副作用（閲覧数・既読・
# 初回作成・履歴・状態遷移）を持つ API は、代理中に 500 にしない／本人のデータを変えないよう分類して扱う。
#
# 書式: <src/main/java/com/mannschaft/app からの相対パス>|<SKIP|DENY|NONE>|<理由>（理由に | は使わない）
#   SKIP … 代理中は副作用だけを行わず、閲覧結果は返す（Service が SupportAccessContextHolder で判定する）
#   DENY … 代理中は拒否する（資格情報・書出し・請求。Service が SupportAccessContextHolder で判定、または @SupportAccessDenied）
#   NONE … GET から副作用に到達しない／副作用が閲覧記録・メトリクスのみ。理由が必須
#
# 洗い出しの起点: GetMapping から呼ばれる非 readOnly の @Transactional、increment*/markAs*/record*、getOrCreate*、
# AFTER_COMMIT の発火、Valkey への書込（opsFor*().set/setIfAbsent/increment/add）、外部送信（メール・Push・Webhook・
# S3 署名 URL の発行）。番人 SupportAccessGuardTest.S14 が、ここに載らない新規の候補（Service.java 内の
# increment*View*/markAsRead*/record*Viewed*/*_VIEWED と、全クラスの Valkey 書込）を検出する。
# 分類を変えるときはこの表と実装を同時に直すこと。
#
# 外部送信の再走査（2026-11-27 検分差し戻し対応A）: メールは mail outbox への INSERT（READ ONLY 接続で不成立）か
# 書込 API の AFTER_COMMIT リスナーからだけ送る。Push（NotificationDispatchService・WebPushService）・Webhook も
# 書込の通知イベントからだけ発火し、GET からは到達しない。S3 署名 URL の発行口（presign*）は、アップロード用が
# POST（SUPPORT_ACCESS_003）、ダウンロード用が download-url／file-links のパス（PathPolicy の 004）で、いずれも
# 代理中の GET からは発行されない。応答 DTO に signedUrl・token 等を持つ GET は @SupportAccessDenied が必須
# （番人 SupportAccessEnforcementGuardTest）。
