# 凱旋（検分 → CI緑裏取り → マージ）

戦（実装）を終えた足軽の成果PRを、**検分で品質を検め・CI緑を実体で裏取りし・mainへマージ**して凱旋させる一気通貫スキル。
マージは merge queue 前提（queue 有効・無効の両方の手順は §4 と `docs/development/merge_queue_operations.md`）。`--admin` の自動許可は廃止した。

> 位置づけ: **設計→軍議→試練→出陣→検分→実機E2E** の後段、「検分〜マージ」を1コマンドに束ねたもの。
> 単発の検分だけなら `/検分`、CI戦況だけなら `/物見` を使う。

## 引数
- `[PR番号]`: 対象PR。省略時は現ブランチに紐づく OPEN PR を `gh pr view --json number` で解決。
- `--admin` は使えない（2026-11-23 Ruleset の bypass を撤去。queue の外で main を動かすと queue 全体が作り直されて詰まるため）。merge queue 自体の障害時のみ、マスター確認のうえで bypass を一時的に戻す（手順は正本）。

## 手順

### 1. 対象PRの特定と前提確認
```bash
gh pr view <PR> --json number,state,headRefName,headRefOid,mergeable,mergeStateStatus
```
- `state=OPEN` を確認。既に MERGED/CLOSED なら退く。
- head SHA を控える（後の裏取り用）。

### 2. 検分（必須・スキップ禁止）
`feedback_inspection_required_before_merge`: **CI通過だけでマージしてはならない。必ず検分を行う。**
- 検分者の既定は `codex`（`.claude/commands/検分.md`）。**Claude 側の Workflow 検分を使いたいときは `/検分 claude` と明示する**（無指定では Codex 検分になり、次元別レビュー＋敵対的検証の Workflow は走らない）。差分が広い/複数観点なら `/検分 both` で両者を独立に当て、殿が指摘を照合するのがもっとも手厚い。
- 受け入れ条件↔テスト↔実装のトレーサビリティ、配線の正確性、**新依存を足したら @InjectMocks 兄弟テストの mock 漏れ**（フルシャードNPEの温床。`project_media_url_resolution_architecture`）を照合。
- 足軽の自己申告は鵜呑みにせず、`git show`/実テスト実走で実体裏取り（`feedback_verify_tool_output_fabrication`）。
- **検分でNGが出たら凱旋を中断**し、足軽に差し戻す。緑になるまでマージしない。

### 完了台帳の証拠確認

戦役台帳の状態を完了へ進める前に、完了証拠JSONを含む変更で次を実行し、成功を確認する。

```bash
node scripts/completion-evidence.mjs --base origin/main --head HEAD
```

証拠JSONの保存先は `docs/evidence/<CMP-ID>.json`。台帳の行は ID の月のファイル `docs/task-list/YYYY-MM.md` にあり（未畳み込みの申告 `docs/task-list/changes/` を適用した実効台帳で読む）、証拠リンクは `../evidence/<CMP-ID>.json`。完了への更新は月別ファイルを直接編集せず `node scripts/task-list-ledger.mjs update <CMP-ID> --set 状態=完了 --set 証拠="[完了証拠](../evidence/<CMP-ID>.json)"` の申告で行う。形式と検査内容は [`docs/development/completion-evidence.md`](../../docs/development/completion-evidence.md) を参照する。

### 3. CI緑の裏取り（偽exit0を信じない・ポーリング枯渇しない）
```bash
rid=$(gh run list --branch <headRef> --limit 1 --json databaseId -q '.[0].databaseId')
gh run view $rid --json status,conclusion -q '"status=\(.status) conclusion=\(.conclusion)"'
```
- **`gh run watch` の exit code を信じるな**（`feedback_gh_run_watch_false_exit0`: cancel/in_progressでもexit0を誤報。この環境では即離脱し `watch_exit=1` でも run は in_progress のまま）。**必ず `gh run view --json conclusion` の実値**で判定。
- まだ `in_progress`（Test shard 実行中は数十分かかる）なら、**低頻度の有界ループ**で完了を待つ（`gh pr checks` の "pending" は走行中を含む＝queue詰まりと誤認しない）:
  ```bash
  for i in $(seq 1 30); do s=$(gh run view $rid --json status -q .status); [ "$s" = completed ] && break; sleep 60; done
  gh run view $rid --json status,conclusion -q '.conclusion'
  ```
  これは `run_in_background` で回し通知を待つ。**連続ポーリング/並行watchは禁止**（`feedback_no_ci_polling_github_ratelimit`: API 5000/hr 全セッション共有・403で全gh停止）。
- 判定: `conclusion=success` かつ `gh pr checks <PR>` が **Failed: 0**。**フルシャード（Test shard 0〜3）が緑**であることを必ず確認（局所実走の緑に騙されない・NPE系はここで初検知）。
- `failure` なら `gh run view $rid --job <失敗job> --log-failed | grep -E "FAILED$|NullPointer|expected:"` で失敗テストを特定→足軽に差し戻し。**マージしない**。

### 4. マージ（gh のみ・本陣git禁止）
`feedback_merge_gh_only_no_honjin_git`: マージは `gh` だけ。本陣 working tree で git 操作しない。運用の正本は [`docs/development/merge_queue_operations.md`](../../docs/development/merge_queue_operations.md)。

**まず queue が有効か Ruleset で確認する**（有効＝merge queue 運用／無効＝移行前・障害時）。

#### queue 有効時（既定）
```bash
gh pr merge <PR> --squash   # 予約。必須チェック未完了なら auto-merge が予約され、緑になると自動で queue へ入る（追従不要。queue 有効時は --delete-branch を付けない。--admin は bypass 撤去済みで使えない）
```
- **コマンド成功＝マージ済みではない**。ブランチ削除は **MERGED（`state=MERGED` かつ `mergedAt` 非 null）確認後**に別手順で行う（CLAUDE.md の事前許可条件＝PR が MERGED・main 反映・HEAD/所有者/他 worktree 未使用を削除直前に確認、を満たすときのみ）。queue 有効時は追従（main 取り込み・`gh pr update-branch`）は不要（strict 解除済みのため）。コンフリクト（`mergeable=CONFLICTING`）のときだけ main を取り込んで解消する。
- **状態判定**（単発・低頻度）:
  ```bash
  gh pr view <PR> --json state,mergedAt,mergeStateStatus,autoMergeRequest,mergeable
  gh api graphql -f query='query{repository(owner:"Mannschaft2026",name:"mannschaft"){pullRequest(number:<PR>){state mergedAt isInMergeQueue autoMergeRequest{enabledAt} mergeQueueEntry{state position}}}}'
  ```
  - (a) PR 側必須チェック待ち: state=OPEN・`autoMergeRequest` 非 null・`isInMergeQueue=false` → 待つ
  - (b) queue 内で検証中: `isInMergeQueue=true`（`mergeQueueEntry.state`・`position`） → 待つ
  - (c) **queue から脱落**（失敗・timeout）: 自分が投入した記録、または timeline の `AddedToMergeQueueEvent` があり、その後 `RemovedFromMergeQueueEvent`（`reason` 付き）が出て、state=OPEN・`isInMergeQueue=false`・未マージ（timeline は `timelineItems(last:5,itemTypes:[ADDED_TO_MERGE_QUEUE_EVENT,REMOVED_FROM_MERGE_QUEUE_EVENT])` で取得）。履歴が不明なら脱落と断定せず「queue 外（未投入／脱落未確定）」と分類する → **完了扱いにせず worktree も撤去しない**。`gh run list --event merge_group --limit 5` と `gh run view <runId> --log-failed` で原因を特定→根治→再投入
  - (d) MERGED: **`state=MERGED` かつ `mergedAt` 非 null** のときのみ完了（§5 へ）
- `--admin` は bypass 撤去済みで通らない。queue 自体の障害時のみ、**マスター確認のうえ**で正本の手順に従い bypass を一時復元する（自動許可なし）。

#### queue 無効時（移行前・障害で無効化中）
admin 自動許可は廃止。worktree 足軽で `git merge origin/main` → push → CI 緑 → `gh pr merge <PR> --squash --delete-branch`（本陣gitは使わない）。strict が効くため BEHIND になれば追従が必要。queue を無効化するときは **strict を必ず同時に復元**する（`docs/development/merge_queue_operations.md`）。

- 直後に**マージ実体を裏取り**（queue 有効時は (d) MERGED になるまで待ってから）（`feedback_verify_tool_output_fabrication`）:
  ```bash
  gh pr view <PR> --json state,mergeCommit -q '"state=\(.state) mergeCommit=\(.mergeCommit.oid[0:9])"'
  git fetch origin main --quiet && git log --oneline -1 origin/main   # mergeCommit が main 先頭に在るか
  ```

### 5. 後片付け（worktree 撤去）
- ローカルブランチ削除が `used by worktree` で失敗するのは、当該ブランチを足軽worktreeが握っているため（正常）。撤去する:
  ```bash
  git worktree remove --force .claude/worktrees/agent-xxxxx
  git branch -D <feature-branch>; git worktree prune
  ```
- **junction注意**（`feedback_worktree_remove_junction_deletes_honjin_node_modules`）: `frontend/node_modules` が本陣へのjunctionなら、`git worktree remove` がjunction先の本陣実体を巻き込み削除する。撤去前に `ls .../frontend | grep node_modules` で確認し、junctionあれば `cmd //c rmdir` でリンクを先に外す（BE-onlyでjunction無ければそのまま撤去可）。

### 5.1 陣払い完了ゲート（必須）

対象 PR の worktree を撤去した後、本陣で必ず次を実行する。

```powershell
node scripts/worktree-cleanup.mjs --days 1 --check --limit 60
```

- 1日超 stale の足軽 worktree が残る、または全 worktree が60本を超えると非0で失敗する。理由を解消するか、dirty/locked/index.lock 等の保全理由を殿へ報告するまで凱旋完了にしない。
- 既定dry-runから `--apply` に進めるのは、clean な `.claude/worktrees/agent-*` かつ `worktree-agent-*` のみ。撤去はworktree登録だけでローカルbranchを削除しない。branch整理は陣払いのPR head SHA/祖先照合手順へ委譲する。feature/非agent/本陣、prunable登録、Git検査失敗には触れない。
- junction（worktree直下・`frontend/node_modules`）は先にリンクだけを外す。スクリプトはリンク先を削除しない。
- 検証用dev サーバ（`:8081`/`:3001` 等）を足軽が起こしていたら、PID cmdline裏取りの上 kill（`wsl --shutdown` 厳禁・本陣8080/3000は触るな）。

### 5.2 WSL検証資産の完了ゲート（必須）

- 新規WSLコピーは `scripts/verification-run.mjs` を通す。Linux/WSLで `node scripts/verification-run.mjs --check` を実行し、自分の要処置パスを確認する。SIGKILL/ホスト障害ではfinallyが動かないため、この確認は省略しない。
- コピー、専用cache、配布物、起動プロセス、検証コンテナ・専用volumeについて自身の所有と用途を確認し、不要分を撤去する。共有cache・管理外既存コピーへ無差別適用せず、全WSL停止・無差別pruneを行わない。
- 必要証跡をCI等の正本へ確定し、重複ローカルrawログ・全量archiveは撤去する。保持するものは正確なパス・所有者・用途・理由・再確認期限・再開条件を記録し、未解消を完了扱いにしない。
- 手順と保持時の調査は `docs/development/worktree_operations.md`「WSL検証コピーの寿命管理」に従う。

## 上奏（マスターへ）
```
🏯殿様:【凱旋】マスター、PR #<n>「<title>」を main へ凱旋させました
- 検分: <合格/差し戻し内容>
- CI: run <id> conclusion=success（フルシャード緑・Failed 0）※実体裏取り
- マージ: MERGED / mergeCommit <sha>（origin/main 先頭に反映確認）
- マージ経路: <queue 経由（state=MERGED・mergedAt 確認）/ queue 無効時の通常マージ / admin（queue 障害・マスター承認の根拠）>
- 後片付け: worktree撤去済・検証サーバkill済・本陣無傷
```

## 禁止事項（凱旋の鉄則）
- **検分せずマージ**（CI緑だけでマージ）
- **`gh run watch` の exit code でCI合否を判定**（必ず `gh run view --json conclusion` の実値）
- **CI連続ポーリング/並行watch**（API枯渇→403で全gh停止）
- **queue から脱落（状態(c)）したまま完了扱い・worktree 撤去**（原因を直して再投入）
- **`gh pr merge` の成功だけでマージ済みと報告**（`state=MERGED` かつ `mergedAt` 非 null で判定）
- **マスター確認なしの `--admin`**
- **本陣 working tree での git 操作**（マージは gh のみ・pre-commitフック/本陣gitガードで機械的に拒否される）
- **足軽の自己申告を無検証で信用**（識別子・マージ結果は `gh --json`＋`git show origin/main` で裏取り）
- **フルシャード未確認でのマージ**（局所緑に騙されない）
