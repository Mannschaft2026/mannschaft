## 言語の切り替え方（アプリの実装の確認結果）

- ログイン中の表示言語は**アカウント言語（`users.locale`）が正**。`plugins/locale.client.ts` が起動時に `authStore.user.locale` で cookie `i18n_locale` と表示言語を上書きするため、cookie だけでは切り替わらない（実機で確認: cookie を `en` にしても `<html lang="ja">` のまま日本語で表示された）。
- 正規の導線は「設定 > 言語とタイムゾーン（`/settings/language`）」の「表示言語」で選んで「保存」。保存は `PUT /api/v1/users/me`。本 spec はこの画面操作で ja → en → de → ja と切り替えた。
- 共有アカウント `e2e-admin` の言語を書き換えるため、spec は開始時の言語（ja）を控え、画面で ja に戻したうえで `finally` でも API（PUT）で復元し、終了時の言語が ja であることを確認する。実測: 終了時のアカウント言語は ja。
- テスト用ログイン補助 `loginViaApi(deferNavigation)` は文書ごとに localStorage の `currentUser.locale` を初期値へ戻す。言語保存後の確認は、アカウント言語で再ログインした新しいセッションで行った（実利用の「保存してから使う」流れと同じ。アプリ側の不具合ではない）。

## 実装欠陥（FAIL）: 通知種別の名前が de/zh/ko/es で日本語のまま

- 再現手順: `e2e-admin` で `/settings/language` を「Deutsch」にして保存 → `/settings/notifications` の「種別」一覧を見る。
- 期待: 通知種別の名前（「予約確定通知」等）がドイツ語で出る。
- 実際: 50 件中 45 件（「スケジュール作成通知」「出欠回答リマインド」「予約確定通知」…）が日本語。画面の FE 文言（見出し・説明・ボタン）は訳で出ている。
- 原因: 表示名は `NotificationPreferenceService.resolveLabel`（`backend/src/main/java/com/mannschaft/app/notification/service/NotificationPreferenceService.java:393`）が `messageSource.getMessage("notification.type.<TYPE>.label", null, <TYPE名>, locale)` で解決して `GET /api/v1/notification-type-preferences` の `label` に入れる。`backend/src/main/resources/messages_de.properties`（zh・ko・es も同様）には `notification.type.*.label` が 5 件しか無く、残りは既定の `messages.properties`（日本語）へフォールバックする（`messages_en.properties` と `messages_ja.properties` は 50 件）。
- 位置づけ: 実装 PR #4739 の変更（FE の直書き解消）の範囲外にある BE 側のロケール欠落。FE の i18n としては合格で、「ja 以外で日本語が画面に残らない」を `/settings/notifications` の通知種別名まで含めて満たすには BE のメッセージ追加が要る。殿の判断を仰ぐ。
