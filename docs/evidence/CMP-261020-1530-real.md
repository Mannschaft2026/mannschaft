# CMP-261020-1530 実機E2E・アリシゼーション記録

OAuth ログインの監査行（LOGIN_SUCCESS）で ip_address と user_agent が入れ替わる不具合の是正（PR #4646）について、実機E2E とアリシゼーションの実施記録。個別のユーザー ID・トークン・個人情報は記載しない。IP は文書用の 203.0.113.x 等のみ。

## 実機E2E（2026-11-19・E1〜E5 合格）

- 条件: origin/main（#4646 のマージコミット）から bootJar を作成した検証 BE（8081）と実 FE。Google は偽プロバイダ（ローカル）で代替した。本陣 8080 には触れていない。
- E1: POST /api/v1/auth/oauth/google に X-Forwarded-For: 203.0.113.45 と識別用 UA を付けて呼ぶと、新規登録は 200、同じ sub での再ログイン（既存連携）も 200。
- E2: audit_logs で LOGIN_SUCCESS の ip_address=203.0.113.45、user_agent=送った UA（取り違え無し）。session_hash は 64 桁で非 null、refresh_tokens の jti は非 null。audit_logs に method 列は無く metadata も NULL で、方式（OAUTH_GOOGLE）は DB に残らない（全方式共通の既存仕様）。
- E3: GET /api/v1/users/me/login-history が 200 で、ipAddress・userAgent が正しい。method は null。
- E4: 別ユーザーの履歴には他人の IP/UA が混ざらない。token なしは 401、不正 token も 401（ロール横断・URL 直打ち相当）。
- E5: ブラウザ（Playwright・Chrome headless）で /settings/login-history に IP と UA が表示された。ja はスクリーンショットを目視した。**en 画面は目視ではなく本文テキストでの確認**（ナビは英語化、見出し・種別・検索欄は日本語のまま）。
- 同時是正: #4646 の範囲で、本番の OAuth ログインが RefreshToken の jti 未設定のため常に 500 になっていた不具合も直した。修正前は既存連携ログインが 500、修正後は 200 を実機で確認した。

## アリシゼーション（2026-11-19）

- 住民 1 体: 一般利用者（素直な操作）が「ログイン履歴画面で自分のログイン記録を確かめたい」。ja/en/de・1280px/360px で実施。
- 到達可否: 画面導線（登録、ログイン、ダッシュボード、サイドバー「設定」、「個別設定一覧」展開、「ログイン履歴」）だけで到達できた。設定の検索ボックス経由でも到達できた。IP・UA・日時・種別は読める。
- 本修正の範囲内で、IP/UA の取り違え・退行は見つからなかった。
- 範囲外の観測（台帳へ別途起票）: FE の Google ログインが BE の引数形式と食い違い 400 になる、OAuth 直発行経路のパリティ欠落、誤パスワードのログイン失敗が記録されない疑い、NEW_DEVICE_LOGIN 行の user_agent が null、ログイン履歴画面の i18n 直書き・method 常時 null・360px での UA 省略・導線の深さ。
- 環境起因の観測: 開発 BE の CORS 許可オリジンに検証用 FE のポートが無く、通信は Playwright 側の回避で通した（アプリの不備とは断定しない）。

## 後始末

作成した検証用ユーザーと関連行は、主キー・ユーザー ID 指定で削除し、全走査で残件 0 を確認した。検証 BE・偽プロバイダ・検証 FE は停止済み。
