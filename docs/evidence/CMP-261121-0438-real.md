# CMP-261121-0438 実機E2E・アリシゼーション記録

OAuth ログイン（2FA 無効で即発行する経路）が refresh 用 Cookie を発行しない不具合の是正（PR #4715、merge commit 0088766666）について、実機E2E とアリシゼーションの実施記録。個別のユーザー ID・トークン・Cookie 値・個人情報は記載しない。画面はテキスト・URL・HTTP ステータス・Cookie 属性で確認し、スクリーンショットの目視は未実施。

## 実機E2E（2026-11-21・J1〜J7 全合格）

- 条件: PR #4715 のブランチ HEAD から bootJar を作成した検証 BE（本陣とは別ポート）と、同ブランチの Nuxt dev（API の向き先は検証 BE）。Google は偽プロバイダ（ローカル）で代替し、Playwright Chromium で「Google でログイン」ボタンを実際にクリックした。共有 DB を使用し、作成したテストユーザーは主キー指定で削除済み（共有の既存ユーザーは無傷）。
- J1: 2FA 無効ユーザーの OAuth ログインで POST /api/v1/auth/oauth/google が 200。access_token と refresh_token の 2 つの Set-Cookie（HttpOnly・SameSite=Strict・Path=/）が付き /dashboard へ。F5 リロード後も維持（session_expired なし）。
- J1b: access_token Cookie を削除してリロードすると POST /api/v1/auth/refresh が 200 で両 Cookie が再発行され /dashboard 維持（refresh_token Cookie が実際に使われている）。
- J2: ログイン直後の新規タブで /dashboard・/settings/security・/teams を直打ちしても /login に落ちず表示。
- 他テナント: 所属しないチームの /teams/<他チーム>/audit-logs は API が 403、/system-admin 直打ちは /dashboard へ遷移拒否（API 呼び出しなし）。audit-logs が API 403 でも画面枠が出るのは CMP-261012-0911 で記録済みの既存事象で本修正とは無関係。
- J3: SYSTEM_ADMIN の OAuth ログインも 2 つの Cookie が付き /system-admin へ。リロード・URL 直打ち後も維持。
- J4: 2FA（TOTP）有効ユーザーの OAuth ログインは 200 だが Set-Cookie なし・ブラウザ Cookie 0 件で /2fa-verify へ。TOTP 入力後の POST /api/v1/auth/2fa/validate で 2 つの Cookie が付き /dashboard、リロード後も維持。
- J5: OAuth 新規登録経路も 2 つの Cookie が付き /dashboard、リロード後も維持。
- J6: logout で両 Cookie が Max-Age=0 で失効し /login へ。リロードは /login のまま、/dashboard 直打ちは /login?redirect=%2Fdashboard。
- J7: パスワードログインの回帰なし（2 つの Cookie・リロード維持）。
- 補足: 偽プロバイダの sub をメールごとに分けておらず J1・J3 の初回は別ユーザーで実行された点と、検証スクリプトの選択子・HTTP メソッドの不備による一時的な FAIL はいずれも検証側の問題で、修正後に全シナリオを取り直して合格した。

## アリシゼーション（2026-11-21・実機後）

- 住民 3 体: ADHD 傾向で中断・放棄する利用者、スマホ片手で素直に操作する利用者、一般利用者で隙間を狙い連打する利用者。実 UI を自律探索し、導線・表示・詰まりを観測した。
- 結果: 確定不備なし。
- 棄却した観測: (1) Cookie のみ復元して /login に落ちる事象は、FE の認証状態が localStorage 由来であることによる検証手順上の現象。(2) /settings からプロフィールへの導線なしは誤認で、frontend/app/pages/settings/index.vue に導線が存在する。(3) callback code の再利用は偽プロバイダの仕様（OAuth の state 欠落は別件として台帳 CMP-261121-1332 に起票済み）。
- 気づき（別件）: access_token 失効直後に API が 3 本ほど一時的に 401 を返し、自力復帰する。全ログイン方式共通の既存挙動で本修正とは無関係。
