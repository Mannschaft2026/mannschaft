組織 e2e には seed 上 MEMBER が居ない（ADMIN 2 名のみ）。そのため beforeAll で、組織 ADMIN が招待トークン（roleId=4=MEMBER・1 回限り）を発行し、どの組織にも未所属の e2e-dummy-20 を参加させ、afterAll でメンバーから外してトークンを失効させる（自分が加えた場合だけ）。実行後に DB で e2e-dummy-20 の組織所属が残っていないことを確認済み。

## ロール横断の結果（画面の文言）

- 権限あり（ADMIN）: 取消・削除ボタンが状態条件どおりに出て、操作が実行され、一覧が更新される。
- 権限なし（MEMBER）: 一覧は見えるが、取消・削除・作成の導線が出ない。API 直接も 403。
- 他テナント（他チーム／他組織の ADMIN・非所属）: 画面は「情報を取得できませんでした」＋「再試行」。API 直接（取消・削除・詳細）は 403 で、対象の回覧は変化しない。

## 発見事項（本 PR のスコープ外・実装欠陥の扱いは殿の判断）

1. **BE が ACTIVE の削除を拒否しない**（既知・台帳 CMP-261121-2128）。実機の準備中に、ADMIN が API で ACTIVE の回覧を `DELETE` すると 204 で削除できることを確認した（画面ではボタンが出ないため、FE の状態条件が唯一の防御になっている）。再現: ADMIN で回覧を作成して activate → `DELETE /api/v1/teams/1/circulations/{id}` が 204。
2. 取消済み（CANCELLED）の回覧の詳細 `GET /api/v1/teams/{id}/circulations/{docId}` は、作成者の ADMIN にも 403（`VISIBILITY_001`）を返す。`CirculationDocumentVisibilityResolver.java:126,140` が CANCELLED を ARCHIVED 扱いにし SystemAdmin のみ可視とする設計どおりの挙動。一方、一覧には CANCELLED の行が残り、行はクリック可能なため、ADMIN が取消済みの行を開くと詳細が取得できない可能性がある（API では確認。画面でクリックしての確認は未実施）。実装欠陥かは殿の判断。
