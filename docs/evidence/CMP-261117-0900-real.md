# CMP-261117-0900 実機検証記録（大会スコープの掲示板カテゴリ一覧 `GET /api/v1/bulletin/categories`）

- 対象: 大会 `TOURNAMENT` ／ ディビジョン `TOURNAMENT_DIVISION` スコープのカテゴリ一覧が、閲覧権あり 200、閲覧権なし・他テナント・不在・未ログインはスレッド一覧 `GET /api/v1/bulletin/threads` と同じ status／エラーコード、非数値 `scope_id` は 400（COMMON_001）。TEAM／ORGANIZATION／VILLAGE は回帰なし。仕様は `docs/features/F05.1_bulletin_board.md`。試験の写し元は `BulletinTournamentCategoryListContractIT`。
- 実施日: 2026-11-18（JST、前日 2026-11-17 夜からの連続作業）。手段: 実 BE への HTTP 実測（認可・契約の検証）と、Playwright（Chromium、実ブラウザ・モックなし）による画面確認。画面側は、大会連絡スペース画面の作成フォームが実際にカテゴリ一覧を呼ぶ経路で踏んだ。
- 環境: BE は **origin/main `51deace6fb`（#4601・#4603・#4589 を含む）から WSL native で bootJar を新規ビルド**（共通入口 `scripts/verification-run.mjs`、`--no-daemon`）して 8081 で起動。実 MySQL・実 Valkey。CORS は OPTIONS で FE のオリジンが 200 になることを実測。FE は同コミットの作業木（`npm ci`）の dev サーバー。
- 前提データは自前（メール・組織・チーム・大会に `e2e-og-r30-` / `r30-` / `R30` の接頭辞）。後始末は報告本文のとおり。
- スクリーンショット: `docs/evidence/screenshots/CMP-261117-0900/`（画面確認は 0859 側の画像も参照）

## 画面での確認

主催組織の管理者（oa）で大会連絡スペース画面を開き、「新規スレッド」を押した。

| 操作 | 結果 |
|---|---|
| 大会全体で「新規スレッド」 | フォームが `GET /bulletin/categories?scope_type=TOURNAMENT&scope_id=<大会ID>` を呼び **200**。カテゴリの選択肢に「お知らせ」「連絡」の 2 件が出る。`0900-oa-form-category-dropdown.png` |
| ディビジョンへ切替えて「新規スレッド」 | `scope_type=TOURNAMENT_DIVISION&scope_id=<ディビジョンID>` で **200** |
| 上記を通して | 4xx/5xx 0 件、トーストなし |

（前回 2026-11-17 の記録では、同じ画面でカテゴリ取得が 403 になり、選択肢が空のままだった。今回は解消。）

## 観測（欠陥ではない・記録のみ）

- 閲覧権のない者に対し、**実在の大会は 403 TOUR_030、不在の大会は 404 TOUR_029** と返り、状態が分かれる。スレッド一覧も同じ挙動で、今回の契約は「カテゴリ一覧をスレッド一覧と同じにする」ことなので不合格にしない。大会 ID の実在が非閲覧者に判別できる点は、別途の方針判断（CMP-261116-0726 の系統）として記録のみ。
- 未ログインは公開設定が非公開のとき 401（実在・不在とも同じ）。

## 判定

**passed**（カテゴリ一覧が閲覧権ありで 200、閲覧権なし・他テナント・不在・未ログインでスレッド一覧と同じ status／コード、非数値 400、TEAM／ORGANIZATION／VILLAGE の回帰なし）。画面（作成フォームのカテゴリ選択）も大会・ディビジョンとも 200 で選択肢が出る。
