## 検証用データ（すべて自分で作成。終了時に撤去済み）

検証専用に、使い捨てのユーザー5名・チーム2・組織2を作成した（チーム管理者A／著者B（非ADMIN）／一般会員C／他チーム・他組織の管理者D／サポーターE）。
お知らせは告知ウィザード（broadcast）で作成。**一般会員は告知を作れない**（403 COMMON_002）ため、著者が非 ADMIN のお知らせは、管理者が作成した行の著者 ID を DB 上で B に付け替えて用意した（著者判定は `author_id` 照合のため、状態としては同等）。
所属は、チーム・組織の作成者は API、それ以外の会員は DB へ直接投入した。**初回は `memberships` 行を入れ忘れ**、会員 C への本文プレビューが 404 になったため（アリシゼーション側に記載）、`memberships` を補ったうえで本記録の第3回を再実行した。

## 対象操作を画面で踏んだ範囲と API を使った範囲

- 画面で通した操作: チーム ADMIN のピン留め・解除・お知らせ解除（R1）、著者・一般会員の導線の有無（R2）、他チーム管理者の一覧 URL 直打ち（R4-url-1）、ブラウザ内からの直接リクエスト（R4-url-2）。
- API を使ったのは、ログイン済みセッションを用いた拒否応答（403/404/401）の status・エラーコード・本文比較と、組織側。**組織ホームの画面ではお知らせ項目が1件も表示されず**（読込の通信エラーも1件観測。アリシゼーション記録 X9 参照）、組織側のピン留め・解除の画面導線を確認できなかったため、組織側の操作は API で確認した。
- 前提データ作成・後始末も API / DB。

## 未実施・範囲外（理由つき）

- **課金による非表示（課金 HIDDEN）**: 課金ゲートの設定（有料化）を伴うため今回は未実施。閲覧不可の挙動は、サポーターが会員限定お知らせを操作する経路（R4-5）で、同じ門を通ることを確認した。課金 HIDDEN 固有の経路は UT / IT 側の担保に委ねる。
- 組織の「著者（非 ADMIN）」: 一般会員は告知を作成できないため、組織側では作成できない（O-5 は著者でない一般会員）。
