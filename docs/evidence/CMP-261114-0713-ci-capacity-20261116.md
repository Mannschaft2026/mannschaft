# CMP-261114-0713 通常 Backend CI の有限容量見直し

[run 43720702097 / attempt 1](https://github.com/kenta-0420/mannschaft/actions/runs/43720702097/attempts/1)、source `2f78df04cc9afb69484769e234e5ea938382d323` の実測を根拠に、通常 PR の test-step 上限を85→95分、job上限を100→110分へ変更する。migration込みの105/120分、6 shard、2 fork、forkEvery 180、テスト選別・必須gateは維持する。環境変数で記録する診断上限も実際の上限と揃える。

## 観測と残容量

shard4（job `132843411618`）は割当523クラス中514開始、513 SUCCESS、失敗0で85分上限に達した。未終端・未開始の計10クラスの歴史重み合計は419.644秒で、2 forkでの単純換算は約3.5分となる。初期化などの余裕を含め10分だけ有限上限を増やし、95分での実完走によって容量を確認する。完走を事前に保証する値ではない。

513クラスの実測合計9035.337秒は歴史重み7365.335秒に対して約22.7%増えた。一方、旧runとの共通104クラスは2899.792→2855.466秒で、全般的な遅化や固定クラスのhangを裏付けていない。再割当によるSpring初期化費用の計上位置の変化を考慮する。資源診断ログは空であり、memory余力は未測定のためfork数は増やさない。

[未登録4クラスの個別重み追加](CMP-261114-0713-shard-weights-delta-20261115.md)の3218行prefixと4件deltaを維持する。失敗runを使った全量重み更新や、正常nightly全6freshというupdaterの条件変更は行わない。

## 独立したfixture失敗

shard3（job `132843411652`）の `BlogPostServiceTest.GetBySlug` 最初のケースは、匿名用の `PaymentGateService.checkAccess(..., null, ...)` stubが未使用となり、Mockitoの `UnnecessaryStubbingException` で失敗した。対象ケースだけ `SecurityUtils.getCurrentUserIdOrNull()` をスコープ付きstatic mockでnullに固定する。可視性判定と課金ゲートへnullが渡ること・全文アクセス状態を検証し、strictnessを維持する。本体の認可・paywall処理は変更しない。このCI redはfixture失敗の証拠であり、製品assertionのredとは扱わない。

局所検証は `BlogPostServiceTest` 全体とworkflow構文・観測wrapperを対象とする。95分容量の実完走は統合後の全CIで確認し、局所greenを全CI成功とは扱わない。
