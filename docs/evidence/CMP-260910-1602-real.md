### なぜ BE を別ポートで起動したか
共有 BE（8080）は `feature.shift-budget.enabled=false`（`application.yml` の既定値）のまま稼働しており、
`/api/v1/shift-budget/**` が全て `503 SHIFT_BUDGET_001 シフト予算機能は無効化されています` を返すため、この機能の画面は 8080 では検証できない。
共有 BE を止めず・再起動せずに済むよう、同一ビルドをフラグ ON で別プロセス（8081）に起動し、FE も別（3002）にした。DB は共有。

## 実装欠陥・気付き

- 本 CMP の受け入れ条件に対する実装欠陥は **無し**（全 PASS）。
- 別件の気付き（本 CMP の射程外。殿の判断に委ねる）:
  1. **BE 起動の仕方で DATE 列が 1〜2 日ずれて保存される現象を観測**。`-Duser.timezone` を付けずに BE を起動した 8081 では、`2045-04-01` で作った割当が DB に `2045-03-30`、画面には `2045-03-31` と出た（会計年度でも同様）。一方、共有 BE（8080）は同じ操作でずれなかった。`-Duser.timezone=Asia/Tokyo` を付けて再起動するとずれは消えた。`TimeZoneConfig` が `@PostConstruct` で JVM 既定 TZ を JST に切り替える一方、`hibernate.jdbc.time_zone=UTC` を使うため、接続初期化の順序によって LocalDate の格納が変わる疑い。本テストは `-Duser.timezone=Asia/Tokyo` 付きの BE で実施した。
  2. BE は存在しない `budget_category_id`（777）の割当を 201 で受け付ける（実在検証が無い）。
  3. 組織管理者向けの導線: `/admin/shift-budget/*` へのリンクはシステム管理者のクイックリンクにしか見当たらず、組織 ADMIN が画面から到達する入口を確認できなかった（このため開始 URL は直打ち）。
