## 実機E2E
### AC-1 期限切れの REQUESTED / REQUIRES_PAYMENT_METHOD
要求行の expires_at を過去へ UPDATE（自作行のみ）してから、候補 ADMIN が承諾 API を呼んだ。

| 条件 | HTTP | コード | 呼出し後の DB 状態 |
|---|---|---|---|
| REQUESTED（実 API で作成した要求）・チーム | 409 | ENTITLEMENT_033（HANDOVER_EXPIRED） | EXPIRED |
| REQUIRES_PAYMENT_METHOD・チーム | 409 | ENTITLEMENT_033 | EXPIRED |
| REQUESTED（実 API で作成した要求）・組織 | 409 | ENTITLEMENT_033 | EXPIRED |
| 上記 EXPIRED になった行へ再承諾 | 409 | ENTITLEMENT_031（承諾不可） | EXPIRED のまま |

エラー応答を返しつつ EXPIRED が commit されている（API 応答後に別接続で DB を読み直して確認）。

### AC-2 ACCEPTED 以降の期限切れ行は承諾 API で EXPIRED にされない
| 条件（期限切れ） | HTTP | コード | 呼出し後の DB 状態 |
|---|---|---|---|
| SWITCHING | 409 | ENTITLEMENT_031 | SWITCHING のまま |
| PARTIALLY_COMPLETED | 409 | ENTITLEMENT_031 | 変化なし |
| MANUAL_INTERVENTION | 409 | ENTITLEMENT_031 | 変化なし |
| ACCEPTED（呼出し者が承諾者とは別人） | 409 | ENTITLEMENT_031 | ACCEPTED のまま |
| ACCEPTED（呼出し者が承諾者本人） | 404 | ENTITLEMENT_030 | ACCEPTED のまま |

- 最後の行は、承諾者本人による再試行を許す既存の仕様（requireAcceptableStatus）により検証が先へ進み、検証用に作った契約行が実在しないため 404 になったもの。EXPIRED には化けていない。ACCEPTED を期限切れで EXPIRED にしない、という AC-2 は満たす。実契約があれば、期限切れでも本人の再試行が Stripe 照会側へ進む（既存設計。変更ではない）。

認可の失敗では EXPIRED の commit は起きない（noRollbackFor を専用例外に限定した設計どおり）。

### AC-3 通知の遷移先
- 旧 payer が実 API で引継を申請すると、候補 ADMIN の通知（BILLING_PAYER_HANDOVER_HANDOVER_REQUESTED）が作成され、action_url は次のとおり。
  - チーム: /teams/{slug}/settings/billing?payerHandoverRequestId={UUID}
  - 組織: /organizations/{slug}/settings/billing?payerHandoverRequestId={UUID}
- 候補 ADMIN が UI ログインし、通知一覧に「請求担当の引継をお願いします」が 2 件出た。クリックすると組織の課金設定ページへ遷移した（404 にならない）。チーム用 URL も直打ちで開けた（見出し「チームの課金・プラン管理」、契約中のプラン表示、コンソールエラー 0）。通知一覧から 2 件目（チーム分）をクリックする確認は、クリックが 1 件目（組織）へ遷移したため、チーム分は URL 直打ちでの確認にとどまる。
- URL 直打ちの結果（課金設定ページ。クエリ付き）:
  | 利用者 | チーム用 URL | 組織用 URL |
  |---|---|---|
  | 候補 ADMIN | 開ける。プラン表示・「プランを変更する」「解約する」あり | 同左 |
  | チーム部員 | 開ける。プランは表示され「プランの変更・解約は管理者のみ行えます」 | 所属外のため API 403。「契約中のプランはありません（フリー）」と表示 |
  | 他テナントの ADMIN | API 403。「契約中のプランはありません（フリー）」と「プランの変更・解約は管理者のみ行えます」を表示 | 同左 |
- 権限のない利用者にも画面の枠は開くが、プラン情報は API が 403 で返さず、画面にも出ない（情報漏えいは無い）。

## アリシゼーション（短縮）
候補 ADMIN として、通知一覧 → 通知をクリック → 課金設定ページ、の順に操作した。
- 通知からの遷移は成功し、表示崩れ・コンソールエラー・行き詰まりは無かった（スクリーンショットで確認）。
- 所見1（承諾画面が無いことは既知・別行。ただし「何をすればよいか分からない」状態）: 通知本文は「請求担当の引継を承諾していただく必要があります」と言うが、遷移先の課金設定ページは payerHandoverRequestId を読まず、引継に関する表示も操作も無い。候補 ADMIN は通知を開いても承諾する方法が分からない。承諾画面の行で解消される見込み。
- 所見2（PR の範囲外）: 他テナントの利用者や所属外の部員が課金設定ページの URL を直打ちすると、権限エラー画面にならずページの枠が開き、「契約中のプランはありません（フリー）」と表示される。API の 403 を「プラン無し」と同じ表示にしており、実際の契約状態とは異なる情報を見せる。ErrorReport の quiet ログが出る。
- 所見3（PR の範囲外）: 期限切れで EXPIRED になった要求の通知は一覧に残り続ける。開いても何も変わらない。
