## 発見した実装欠陥

**`failed-events.vue` は一覧取得の失敗（403 等）を握りつぶし、「失敗イベントはありません」と表示する。**

- 再現: 組織の一般 MEMBER（または非所属ユーザー）で、組織 11 のスコープのまま `/admin/shift-budget/failed-events` を直打ちする。
  期待: 取得失敗の表示（他 3 画面と同じ「この画面をご利用いただけません」）。実際: 「失敗イベントはありません」の空状態。
- 該当: `frontend/app/pages/admin/shift-budget/failed-events.vue` の `load()` の `catch`（`notification.error` のみで、エラー状態を保持せず `events` を空のまま描画）と、テンプレートの `#empty` スロット。
- 背景: CMP-260909-0543 が同型の欠陥を allocations / dashboard / alerts で直したが、failed-events は「CMP-260909-0544 側」として範囲外にされ、0544 の PR #4743（FE の表示内容のみ）でも直っていない。どちらの台帳行でも担当されていない状態。

## 投入データと制約

- 投入した 5 種別（CONSUMPTION_RECORD×2・CONSUMPTION_CANCEL・THRESHOLD_ALERT・WORKFLOW_START・NOTIFICATION_SEND）は状態も PENDING/RETRYING/EXHAUSTED/MANUAL_RESOLVED を含む。
- **未知の種別は DB の CHECK 制約 `chk_sbfe_event_type` が拒否するため実 DB には投入できない**。FE の未知種別の分岐（生コードを出さず「不明な種別」）は単体テスト（`failed-events.spec.ts`）の範囲で、実機では未確認。
- DB 接続先は環境変数 `E2E_MYSQL_CONTAINER` / `E2E_MYSQL_USER` / `E2E_MYSQL_PASSWORD` / `E2E_MYSQL_DATABASE` で上書きできる（既定はコンテナの既定）。
- 画面は error_message を表示せず、API 応答にだけ SQL 全文が含まれる（FAILED-AC1-01 で事実を確認）。BE 側の分離は CMP-261121-2129。

## FAILED-04 の欠陥の原因と再現手順（修正せず記録。殿が別行で起票）

- 原因: `frontend/app/pages/admin/shift-budget/failed-events.vue` の `load()` の `catch`（`notification.error` のみ。エラー状態を保持せず `events` が空のまま）と、テンプレートの `<DataTable v-else>` の `#empty` スロット（`shiftBudget.failedEvent.empty`）。`allocations.vue` の `loadFailed` / `DashboardErrorState` に相当する分岐が無い。
- 再現: 組織の一般 MEMBER または非所属ユーザーでログインし、組織 11 のスコープ（`currentScope` が組織 11）で `/admin/shift-budget/failed-events` を直打ちする。BE は `GET /api/v1/shift-budget/failed-events` を 403 で返すが、画面は「失敗イベント管理」の表と「失敗イベントはありません」を表示する。
