  期待: 取得失敗の表示（他 3 画面と同じ「この画面をご利用いただけません」）。実際: 「失敗イベントはありません」の空状態。

- 背景: CMP-260909-0543 が同型の欠陥を allocations / dashboard / alerts で直したが、failed-events は「CMP-260909-0544 側」として範囲外にされ、0544 の PR #4743（FE の表示内容のみ）でも直っていない。どちらの台帳行でも担当されていない状態。

## AC-1 が未実施の理由（失敗イベントを発生させる正当な操作を BE から探した結果）

- 失敗イベントを作る API は無い。BE 内部の処理が例外を捕まえたときにだけ記録される（`ShiftBudgetFailedEventService#recordFailure` の呼び出し元を全て確認）。
  - **シフト公開後の消化記録**（`ShiftBudgetConsumptionRecordListener`）: 公開前の検証が「正数の時給が無い」ことを `SHIFT_047` で拒否するため、時給欠落・非正数の経路には到達できない（実機でも `PUBLISHED` が 400 になることを確認し、作ったシフト・割当は削除済み）。消化記録は再公開に対して冪等で、通常操作では例外にならない。
  - **月次締めバッチ（closeAll）**の組織単位の例外、**100% 到達時のワークフロー起動失敗**、**通知配送の失敗**: いずれも BE 内部の障害が前提で、画面・API から正当に起こせない。
- 共有 DB への直接 DML は禁止のため、行を直接挿入していない。
