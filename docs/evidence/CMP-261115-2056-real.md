## 根本原因（観測）

組織所属チーム一覧 `GET /api/v1/organizations/{slug}/teams` の応答は、`id` に **スラッグの文字列**（`slug` と同値）を返し、数値 ID を持つキーは `memberCount` のみ。FE の型は `id: number` と宣言している。ピッカーはこの `id` をそのまま宛先に入れるため、要求本文の対象が `{"type":"TEAM","id":"<slug 文字列>"}` になる。BE の宛先は `Long` で、起動ログに `Cannot deserialize value of type java.lang.Long from String` が出て 400 になる。

また、保存済みグループの対象は数値 ID なので、候補の解決キー（`TEAM:<slug>`）と一致せず、一覧の表記が「チーム #数値」に戻る。

## 判定

**failed**。候補が出る・エラートースト（開くたび）が消えるという D-F2 の中心症状は解消したが、完了条件の「宛先グループの対象がチーム名で表示される」を満たさず、さらに配下チームを選ぶと見込み確認・送信・グループ保存が 400 になる（候補は出るが使えない）。新規欠陥 D-F4 として CMP-261115-2056-exploratory.md に記録した（台帳には未起票）。
