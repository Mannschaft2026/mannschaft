## ロール横断の結果と画面の文言
- 権限あり（CHAIR / SECRETARY）: 「伝達する」ボタン表示・配信可。
- 権限なし（委員会の MEMBER）: 履歴は閲覧可、ボタンなし（`05-member-no-button.png`）。直接 POST は 403。
- 委員会外の組織メンバー・他組織ユーザー: URL 直打ちで「伝達履歴」見出しの下に「ただいまデータを読み込めません／一時的な問題の可能性があります。少し時間をおいて、もう一度お試しください。／再試行」、右上の通知に「エラーが発生しました／この操作を行う権限がありません」（`06-*-direct-url.png`）。履歴の行・ボタンは出ない。API の GET/POST は 403/404。
- 観察（欠陥ではないが UX）: 権限エラーでも本文は「一時的な問題の可能性」の文言になり、「再試行」を押しても直らない。

## 発見した実装欠陥（直していない）
1. **配信の範囲（targetScope）が配信先に反映されない**（CD-E2E-09）
   - 再現: 委員長が画面で範囲「組織全体」・お知らせ投下 ON で配信 → 履歴の行は「組織全体」と出るが、委員会外の組織メンバーの `GET /api/v1/organizations/{orgId}/announcements` は空（`{"data":[]}`）。
   - 期待（設計書 F04.10 L550/L604-606）: PARENT_ORG なら ORGANIZATION スコープのお知らせを生成。実際: `CommitteeDistributionService.distribute` は `targetScope` を履歴に保存するだけで、お知らせを常に `AnnouncementScopeType.COMMITTEE` で生成し、確認通知の受信者も常に現役委員のみ。
   - 影響: 画面で「組織全体」「組織＋加盟チーム＋下位組織」を選べるが、実際は委員会内にしか届かない。
   - なお、委員会内（COMMITTEE_ONLY）への確認通知は届く（CD-E2E-03、MEMBER の確認待ちが1件増加）。
