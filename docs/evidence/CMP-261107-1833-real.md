# CMP-261107-1833 実機E2E・アリシゼーション記録

招待付き新規登録が必ず ROLE_002 で失敗する不具合の根治（登録時は保留として記録し、ログイン後に本人が承認して参加する方式）について、実機E2E とアリシゼーションの実施記録。実装は PR #4767（BE）、#4819（FE）、#4832（再招待依頼の受け手側）。個別のユーザー ID・メールアドレス・トークン・認証コードは記載しない。「目視」はスクリーンショットを実際に開いて確認したもの、それ以外は画面テキスト・HTTP ステータス・DB の状態で確認したもの。

## 分離 PR の特性試験 F2 の反転

分離 PR（CMP-260826-1457）の設計書（.claude/campaigns/2026-11-08-cmp1457-invite-accept-split.md）は、招待付き登録の不具合を別戦役とし、特性試験 F2 で現行挙動（有効な招待付きの登録が ROLE_002 で失敗し、users 行・claim・メール確認トークン・UserRegisteredEvent が残らない）を固定していた。本戦役の PR #4767 でこの期待値を反転した。InviteAcceptanceParityIT の F2 は、登録 200、users は PENDING_VERIFICATION、保留 1 行（ハッシュのみ）、used_count と claim と権限と在籍は 0、UserRegisteredEvent あり、という新しい挙動を固定している（TEAM / ORG）。

## 実機E2E PR1・PR2（2026-11-23・J-S1〜J-S8 合格）

- 条件: 検証 BE（専用スキーマ・専用 Valkey 番号・本陣の BE とは別ポート）と、同 commit の FE（Nuxt dev）。メール確認は、確認トークンのハッシュを既知の値に差し替えて実 UI で開く方式で代替した。宛先付き招待・招待の失効は DB の値で再現した。ベータ制限は ON で実施し、通常登録の回帰の間だけ OFF にした。画面操作は実 UI（Playwright・Chromium）。API は前提データ・DB 確認・他人の保留への直打ちだけに使った。
- J-S1: 公開チームの招待から /register?invite= で登録、メール確認、ログイン、ダイアログで「参加する」、在籍（MEMBER 1 行・claim GRANTED・used_count 加算）まで合格。
- J-S2: 「断る」は DECLINED で参加なし、DECLINED への承認の直打ちは 409 AUTH_085。「あとで」は同一セッションで再表示されず、新しいセッションで再表示された。
- J-S3: 14 歳は同意待ちの間、保留の取得が 403 AUTH_070 で保留は PENDING のまま。保護者の承認後、トークン更新を経てダイアログが出て参加できた。ただし既存欠陥 2 件により自然な導線では完走できない（迂回して検証）。本戦役の範囲外として別行で扱う。
- J-S4: 公開チームの失効は参加申し込みへのリンク（実際に申請して受理）、非公開チームは再招待の依頼ボタン。依頼通知は招待権限者だけに届いた。
- J-S5: 宛先付き招待で別人が登録すると 403 AUTH_083、users も保留も作られない。
- J-S6: 他人の保留への各 POST は 404、自分の保留だけが変化し、他人の保留は前後で完全に一致。未認証は 401。応答にハッシュを含まない。
- J-S7: 権限あり・一般メンバー・無関係ユーザー・他テナント ADMIN の 4 視点で URL 直打ち。権限のない視点は 403 または取得失敗の画面で、情報は漏れなかった。
- J-S8: ベータ OFF の通常登録・ログイン済みの従来の招待参加は回帰なし。

## アリシゼーション PR1・PR2（2026-11-23）

住民 4 体（IT 不慣れな保護者、ADHD 傾向の中学生、招待を出したチーム ADMIN、スマホ片手の多言語利用者）が実 UI を探索した。確定不備は 2 件（いずれも殿が再現して裏取り）。

- A-1: 招待リンクから直接参加した後も、保留が PENDING のまま残り「参加しますか」のダイアログが再び出る。後続の PR で、在籍済みなら JOINED に寄せて解決した。
- A-2（導線の欠落）: 再招待を依頼された ADMIN が、誰の依頼かを知り、依頼者へ渡す手段が画面に無い。受け手側の欠落であり、PR3（#4832）で根治した。
- 改善提案: メール確認後の案内、未ログインの招待ページにチーム名が出ない（既存設計）、「あとで」の後の再表示手段、日本語の余分な空白、360px でのボタンの折り返し。
- 誤報として弾いたもの: 画面が早すぎる撮影による空表示、通知を押しても遷移しないという報告（再現せず）、他チームの管理画面が見えるという報告（作成者として ADMIN であり仕様どおり）。

## 実機E2E PR3（2026-11-24・J1〜J8 合格、不具合 1 件は修正済み）

対象は PR #4832 の再招待依頼の受け手側。TEAM と ORG それぞれに、非公開スコープ、ADMIN 2 名、副管理者（INVITE_MEMBERS あり・なし）、一般メンバー、他テナントの ADMIN を用意した。

- J1: 失効、依頼、お知らせと司令塔、欄、再招待、依頼者への通知、ダイアログ、参加、欄から消えるまで一気通貫で合格（TEAM / ORG）。「あとで」の後でも、通知（?pendingInvite=open）でダイアログが再表示された。
- J2: 見送り（確認ダイアログ、通知、案内、閉じる、以後出ない、再依頼は 409）。
- J3: スコープのダッシュボードの承認待ち、管理ハブのバッジ、内訳行から欄への遷移。
- J4: 権限あり・なしの副管理者、一般メンバー、他テナント ADMIN、未認証の URL・API 直打ち。権限のない視点は欄も行も通知も出ず、API は 403 COMMON_002、他スコープの ID は 404 ROLE_016。
- J5: 元が ADMIN ロールの招待でも MEMBER で付与・参加できた。
- J6: 同時操作（再招待と見送り）は片方だけが勝ち、有効なトークンは 1 件。二重押しも 1 回だけ。
- J7: 360・390 幅で横はみ出しなし、ボタンは全幅・高さ 44px。
- J8: 招待付き登録から参加までの回帰。
- 不具合 D-1（中）: 依頼済みのダイアログの「閉じる」が依頼を DISMISSED にし、依頼を取り下げてしまっていた。殿の裁定で、依頼済みの状態への dismiss は 409 AUTH_085 とし（取り下げは機能として用意しない）、FE の「閉じる」は端末側で閉じるだけにして修正した。
- 観察（要判断）: 再招待で作った宛先付きトークンが、管理者の招待リンク一覧に誰宛てか分からないまま混ざる。

## アリシゼーション PR3（2026-11-24 に一度中断、2026-11-25 に再実施）

初回はディスク空きが規定の下限を割ったため、住民を起動せずに中断した。空きを回復してから、同方式で住民 4 体を再実施した。

- 本流（依頼、再招待、見送り、参加）、モバイル幅、二重押しに不備なし。
- V-1（確定不備・導線の欠落、重大度 低〜中）: 権限を外された元の招待権限者が、古い再招待依頼の通知を押すか /teams/&lt;slug&gt;/invites を直打ちすると、権限が無い旨の案内なしにチームのトップへ戻され、通知は処理できないまま残る。台帳へ起票。
- V-2（改善提案・要判断）: 管理者の個人ダッシュボードで、司令塔が「対応が必要な項目はありません」と出す一方、承認待ち 1 件（再招待の依頼）が並ぶ。台帳へ起票。
- 改善提案: 参加後の完了表示、参加後も残る「承認してください」の通知、「あとで」の後に保留中の招待に気づく場所、「再招待する」に確認が無い非対称、対応後も未読で残る通知、#reissue-requests の Vue Router 警告。台帳へ起票。
- 範囲外の観測（未確定）: 副管理者の /members に「除外」ボタンが見える。仕様どおりかを台帳で確認する。
- 既知の追加観測: createInviteToken と InviteIssuerPolicy で招待権限の範囲がずれている（R-5）。台帳へ起票。
